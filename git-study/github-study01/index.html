코드 컨벤션과 패키지 관리

PEP 8 — 파이썬 코드 컨벤션

파이썬 코드의 가독성과 일관성을 위한 공식 가이드라인입니다.

AI 실무에서 팀원과 협업할 때 가장 기본이 되는 규칙들입니다.

인덴테이션 (들여쓰기)

::: warning 4칸 스페이스를 사용합니다. 탭을 사용하지 마세요. :::

`python

✅ 좋은 예시

def mean(values): total = sum(values) return total / len(values)

❌ 나쁜 예시

def mean(values): return total / len(values) `

줄 길이

::: tip 한 줄의 길이는 79자 이하로 유지하세요. 긴 코드는 괄호를 활용해 여러 줄에 나눠서 작성합니다. :::

`python

✅ 좋은 예시 — 괄호를 사용한 줄 나누기

from typing import ( Optional, List, )

import os import numpy as np

❌ 나쁜 예시 — 한 줄이 너무 김

import extremely_long_package_name_for_something_that_exists `

함수와 변수명 규칙

구분 규칙 예시
함수/변수 snake_case (소문자 + 언더스코어) load_data, model_config
클래스 PascalCase (대문자로 시작) TextClassifier, DataModule
상수 ALL_CAPS (전부 대문자) MAX_LEN, LEARNING_RATE

import 규칙

::: tip import는 다음 순서로 구분해서 작성하세요.

  1. 표준 라이브러리 (os, sys)
  2. 서드파티 패키지 (numpy, orch)
  3. 로컬 모듈 (현재 프로젝트의 파일들) :::

`python

✅ 좋은 예시

import os from typing import Optional, List

import numpy as np import pandas as pd

from my_module import load_data, train_model

def predict(texts: list[str]) -> list[str]: …

Optional 사용법

Optional[T]는 T | None을 의미합니다. 기본값이 없을 때 사용합니다.

`python from typing import Optional

✅ 좋은 예시

def get_user(id: int) -> Optional[dict]: “““사용자를 찾으면 dict, 없으면 None””” …

❌ 나쁜 예시 — 타입 없이 반환 유형 모호

def get_user(id: int): … `

pyproject.toml — 현대적 프로젝트 설정

pyproject.toml vs requirements.txt

구분 pyproject.toml requirements.txt
포맷 TOML (설치 가능 버전 포함) plain text (버전 고정)
메타데이터 프로젝트 이름, 설명, 버전 저장 없음
의존성 관리 uv add로 자동 관리 수동 작성
빌드 시스템 pyproject.toml에 직접 명시 필요 별도 설정 필요

pyproject.toml 예시

` oml [project] name = “my-ml-project” version = “0.1.0” description = “AI 분석을 위한 머신러닝 프로젝트” requires-python = “>=3.12” dependencies = [ “pandas>=2.2.0”, “numpy>=1.26.0”, “torch>=2.1.0”, ]

[project.optional-dependencies] dev = [ “pytest>=8.0.0”, “ruff>=0.4.0”, ] `

pyproject.toml 사용법 

# 의존성 추가 — 버전 충돌 자동 해결
uv add pandas
uv add "pandas==2.2.0"  # 특정 버전

# dev 의존성 추가
uv add --dev pytest ruff

# 의존성 제거
uv remove pandas

# 프로젝트 트리 확인
uv tree

# lock 파일 생성 (모든 의존성 고정)
uv lock

uv — 빠른 패키지 관리자

uv vs pip 비교

기능 pip (기본) uv
설치 속도 느림 (Python으로 작성) 매우 빠름 (Rust 기반, 10~100배 빠름)
가상환경 venv 별도 실행 필요 내장 (uv venv)
의존성 관리 수동 버전 충돌 해결 자동 버전 충돌 해결 (uv.lock)
패키지 검색 PyPI 직접 조회 내장 패키지 검색 (uv search)

uv 주요 명령어 

# 1. 가상환경 생성
uv venv                          # 기본 Python 사용 (.venv 생성)
uv venv myenv                    # 이름 지정
uv venv --python 3.12            # 특정 Python 버전
uv venv --seed                   # pip 패키지도 초기화

# 2. 패키지 설치 (가상환경 자동 활성화)
uv pip install pandas numpy      # 여러 패키지
uv pip install -r requirements.txt
uv pip install "pandas==2.2.0"   # 특정 버전
uv pip uninstall pandas          # 제거
uv pip list                      # 설치된 패키지 목록

# 3. uv run — 가상환경 없이 바로 실행
uv run python main.py            # .venv 자동 관리
uv run --with pandas python -c "import pandas; print(pandas.__version__)"

# 4. 프로젝트 초기화
uv init                          # 기본 프로젝트 생성 (main.py, pyproject.toml 등)
uv init my-project               # 이름 지정

# 5. 동기화
uv sync                          # uv.lock 기준 모든 의존성 설치/동기화

코드 컨벤션 체크리스트

  • 인덴테이션은 4칸 스페이스 사용
  • 한 줄 길이는 79자 이하
  • 함수는 snake_case, 클래스는 PascalCase
  • 상수는 ALL_CAPS (모듈 레벨에서만)
  • import 순서는 표준라이브러리 → 서드파티 → 로컬
  • 타입 힌트는 모든 함수에 명시
  • docstring은 Args/Returns 섹션 포함
  • is/has/can 등 boolean 반환 함수는 접두사 사용
  • Bare except 대신 구체적인 예외 처리 (except ValueError)

왜 코드 컨벤션이 중요한가?

  1. 가독성: 코드 리뷰를 빠르게 할 수 있고, 새 멤버도 쉽게 이해할 수 있음
  2. 자동화 도구 통합: Black, Ruff, isort 등 자동 포맷터와 완벽 호환
  3. 에러 방지: 명명 규칙이 일관되면 IDE 자동 완성 정확도 상승
  4. 팀 협업: 코드가 모두 같은 스타일이면 diff가 깔끔해지고 리뷰 효율이 올라감
