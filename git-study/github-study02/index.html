Git 설치부터 첫 커밋까지

Git이란?

Git은 분산 버전 관리 시스템입니다.

파일을 변경할 때마다 스냅샷을 저장하고, 언제든지 이전 상태로 돌아가거나 새로운 방향으로 작업을 나눌 수 있습니다.

Why not SVN? SVN은 중앙 집중식이라 서버가 다운되면 모든 작업이 중단됩니다. Git은 로컬에 전체 히스토리가 있어서 온라인 상태가 아니어도 안심하고 커밋할 수 있습니다.

Git의 4가지 구성 요소

  1. Blob — 파일 내용 (실제 데이터)
  2. Tree — 폴더 구조 (파일과 하위 트리를 참조)
  3. Commit — 스냅샷 + 메타데이터 (저장일, 작성자, 메시지)
  4. Tag — 커밋에 이름 붙이기 (버전 표시용)

Git 설치 및 초기 설정

설치 

# Windows — https://git-scm.com 에서 다운로드 후 실행
# macOS — brew install git 또는 Git for Mac
# Linux — sudo apt install git (Ubuntu/Debian)

전역 설정 (한 번만)

전역(–global) 설정은 컴퓨터 전체에 적용됩니다.

로컬(–local) 설정은 특정 프로젝트에만 적용되므로, 대부분 –global을 사용합니다.

git config --global user.name "elice"
git config --global user.email gitaccount@elice.com

# 설정 확인
git config --list

버전 확인 

$ git --version
git version 2.17.2 (Apple Git-113)

Git 프로젝트 시작하기

새 프로젝트 생성 

# 프로젝트 폴더에서 초기화
git init
Initialized empty Git repository in /path/to/project/.git/

git init하면 숨김 폴더 .git이 생성됩니다.

여기가 모든 히스토리가 담기는 저장소입니다.

이 폴더를 삭제하면 모든 기록이 사라지니 주의하세요.

Working Directory ↔ Staging Area ↔ Repository 흐름 

Working Directory    →  Staging Area (git add)  →  Git Repository (git commit)
(변경한 파일들)         (커밋할 파일 선택)           (영구 저장)
     Untracked              Staged                      Committed

단계별 커밋 흐름

1단계: git add (스태징에 담기) 

# 특정 파일만 스태징
git add comment.js

# 전체 파일 스태징 (권장)
git add .

git add .은 새로운 파일과 변경된 파일 모두를 포함합니다.

.gitignore에 있는 파일은 제외됩니다.

2단계: git commit (저장소에 저장) 

# 메시지 붙여서 커밋
git commit -m "Initial commit"
# 또는 --amend로 마지막 커밋 수정
git commit --amend

작업 상태 확인 — git status 

$ git status
On branch master

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        article.js
        comment.js
        user.js

nothing added to commit but untracked files present
상태 의미 해결 방법
Untracked 추적되지 않는 새 파일 git add
Staged (Changes to be committed) 커밋 준비 완료 git commit 또는 git reset 취소
Modified (changes not staged) 변경했지만 스태징 안 함 git add 또는 무시

변경 내용 확인 — git diff 

# Working Directory ↔ Staging Area 차이
git diff

# Commit ↔ Staging Area 차이
git diff --cached

커밋 히스토리 보기

기본 로그 

$ git log
commit d78ade4c54fbfe333a466c78f4c2ca66d63d6053 (HEAD -> master)
Author: Elicer <elice@elice.io>
Date:   Tue Dec 11 22:23:13 2018 +0900

    Initial commit

커밋 메시지만 한 줄로 보기 

git log --pretty=oneline
d78ade4 Initial commit
a522b90 init git

그래프 형태로 보기 (브랜치 관계 파악에 필수) 

$ git log --graph --all --pretty=oneline
* 3bf1a8... merging(HEAD -> master)
|\
| * 782d90... add like_feature
* | c3360a... add master
|/
* 1c7881 init git

특정 함수가 바뀐 커밋 찾기 

git log -S function_name

왜 Git을 사용하는가?

  1. 실수 복구: 어떤 변경이든 언제든지 되돌릴 수 있음
  2. 실험 안전: 새로운 기능을 브랜치에서 먼저 시도하고, 실패해도 메인에 영향 없음
  3. 협업: 여러 사람이 동시에 다른 파일을 편집해도 충돌 없이 합칠 수 있음
  4. 变更记录: 누가 언제 무엇을 변경했는지 전체 이력 추적 가능

정리

명령어 역할
git init 새 Git 저장소 생성
git add 파일을 스태징 영역에 추가
git add . 모든 변경 파일을 스태징
git commit -m “message” 스태징된 내용을 저장소에 커밋
git status 현재 작업 상태 확인
git log 커밋 히스토리 보기
git diff 변경 내용 비교
git –amend 마지막 커밋 수정 (메시지나 내용)
