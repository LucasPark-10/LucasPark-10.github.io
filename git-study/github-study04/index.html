Git 원격 저장소 관리

원격 저장소란?

로컬 Git 저장소를 **서버(GitHub, GitLab)**와 연결하여 협업하는 기능입니다.

로컬에 있는 코드를 서버에 올리고(Push), 서버에서 최신 코드를 내려받을 수 있습니다(Pull).

로컬 PC (Git)          ↔      원격 서버 (GitHub/GitLab)
  Working Directory    push ← →   Remote Repository
       ↓ fetch                     ↑ pull
     Staging Area                  Commit History
       ↓ commit
     Local Repository

Git Clone — 원격 저장소 복제

원격 저장소에서 프로젝트 받아오기 

$ git clone https://github.com/username/project.git
Cloning into 'project'...
remote: Enumerating objects: 5, done.
remote: Counting objects: 100% (5/5), done.
remote: Compressing objects: 100% (3/3), done.
remote: Total 5 (delta 0), reused 5 (delta 0)
Receiving objects: 100% (5/5), done.

HTTPS 클론을 권장합니다. HTTP은 암호화되지 않은 데이터를 전송하므로 보안상 위험합니다.

SSH 클론도 좋지만, 초기 설정이 필요합니다.

Remote — 원격 저장소 연결 및 관리

원격 저장소 등록

새 프로젝트에서 원격 저장소를 처음 연결할 때:

# origin이라는 이름으로 원격 저장소 등록
git remote add origin https://github.com/group/project.git

현재 연결된 원격 저장소 확인 

$ git remote
origin              # 기본 원격 저장소 이름

$ git remote -v     # URL도 함께 보기
origin  https://github.com/group/project (fetch)
origin  https://github.com/group/project (push)

원격 저장소 정보 보기 

$ git remote show origin
* remote origin
   Fetch URL: https://github.com/.../git_test.git
   Push URL: https://github.com/.../git_test.git
   HEAD branch: master
   Remote branch:
      master tracked
   Local ref configured for 'git push':
      master pushes to master (up to date)

원격 저장소 이름 변경 / 삭제 

# 이름 변경
$ git remote rename origin git_test
origin  →  git_test

# 삭제
$ git remote rm git_test

Origin — 기본 원격 저장소

origin은 git clone할 때 자동으로 붙여지는 원격 저장소의 기본 이름입니다.

“원본"이라는 뜻이므로, cloned된 프로젝트의 본고장(소스)를 가리킵니다.

# origin 말고 다른 이름으로 연결하고 싶을 때
$ git remote add myproject https://github.com/group/project.git
$ git remote
myproject
origin

# 여러 원격 저장소 관리 가능 (GitHub + GitLab 동시 사용 등)

Git Push — 로컬 → 원격 

# master 브랜치를 origin으로 푸시
git push origin master

# 현재 브랜치를 origin으로 푸시 (단축형)
git push

# 처음 푸시할 때는 --set-upstream 필요
git push --set-upstream origin master

푸시 전 체크리스트

  1. git remote add로 원격 저장소 등록 ✅
  2. git fetch로 최신 상태 확인 ✅
  3. 충돌 없으면 바로 git pull 또는 직접 git push ✅

Git Pull vs Fetch — 핵심 차이

명령어 동작 결과
git pull fetch + merge (한 번에) 원격의 변경을 자동으로 병합
git fetch 원격에서 다운로드만 로컬에는 반영 안 함, 확인 후 수동 merge

git pull (간단하지만 위험할 수 있음) 

$ git pull
remote: Enumerating objects: 5, done.
remote: Counting objects: 100% (5/5), done.
remote: Total 3 ...
Unpacking objects: 100% (3/3), done.
From https://github.com/.../git_test
    0daf5d2..c61952d master -> origin/master
Updating 0daf5d2..c61952d
Fast-forward
 README.md | 1 +
 1 file changed, 1 insertion(+)

git pull은 fetch + merge를 한 번에 합니다.

충돌이 발생하면 자동으로 알려주니 안심하고 사용하면 됩니다.

다만, 로컬에 스테이지되지 않은 변경사항이 있으면 에러가 납니다.

git fetch (안전하게 최신 확인) 

# 원격에서 변경 내용만 다운로드
$ git fetch
remote: Enumerating objects: 5, done.
remote: Counting objects: 100% (5/5), done.
remote: Compressing objects: 100% (2/2), done.
remote: Total 3 ...
Unpacking objects: 100% (3/3), done.
From https://github.com/heeguchi/git_test
    c61952d..932dd32 master -> origin/master

# 어떤 게 바뀌었는지 확인 (로컬에 반영 안 됨!)
$ git log origin/master

# 수동으로 merge (원하는 시점에)
$ git merge origin/master
Updating 932dd32..8a9ed03
Fast-forward
 README.md | 1 +
 1 file changed, 1 insertion(+)

fetch를 먼저 하는 이유: 로컬에 반영하지 않고 먼저 원격의 변경 내용을 확인할 수 있어서 실수 방지에 좋습니다. CI/CD 파이프라인에서 주로 사용합니다.

origin/master — 병목 전략 요약 

# 1. git remote add origin (처음 한 번만)
$ git remote add origin https://github.com/group/project.git

# 2. git fetch로 최신 확인
$ git fetch

# 3. git pull로 병합 (또는 fetch + merge 분리)
$ git pull

# 4. 변경 후 push
$ git push origin master

왜 원격 저장소 관리가 중요한가?

  1. 백업: 로컬 PC가 망가져도 서버에 원본이 있음
  2. 협업: 여러 사람이 같은 프로젝트를 동시에 작업 가능
  3. 커뮤니케이션: Pull/Merge Request로 코드 변경을 공유하고 리뷰받음
  4. CI/CD: 푸시 시 자동으로 테스트 → 빌드 → 배포 연결
